# 21｜用 React Flow 表达风险关系

### 图是界面视图，不是风控结论

React Flow 提供节点、边、缩放和平移；本应用映射固定节点位置。应用负责把 API 返回的图数据映射为自定义客户、账户、交易和对手方节点。用户能追踪邻接关系，但不能把节点距离或颜色直接解释成概率。

关系图必须与案件 ID 对齐，切换标签或案件后不能留下旧节点；没有关系时应清楚说明，而不是渲染假数据填空。

### 练习与本章小结

<!-- page -->

**练习**

1. 哪些视觉属性能帮助区分节点类型，又不会暗示未经证实的风险概率？
2. 交互图的坐标是否应该作为持久业务数据？
3. 对每条关系，如何让分析员一跳返回原始交易或记录理由？

**参考解**

1. 标签、类型名与独立图标表达对象种类；高亮只标告警主体。颜色和距离不能解释成欺诈概率或控制关系。
2. 当前实现由类型列和行计数计算固定节点位置，draggable:false；缩放/平移只改变视图。没有把坐标写回领域或数据库，也不应把布局当证据。
3. API 用稳定节点/边 ID 与 rationale 保留来源，界面通过选择节点和关联记录解释事实。并非每条边都提供独立URL跳转；缺少这种交互时不能在教材声称已实现。

**小结**：React Flow 提供探索交互；图数据来自后端持久化事实。视觉布局不等于因果、控制关系或风险证明。
