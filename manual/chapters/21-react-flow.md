# 21｜用 React Flow 表达风险关系

### 第 1 页｜图是界面视图，不是风控结论

React Flow 提供节点、边、缩放和布局交互。应用负责把 API 返回的图数据映射为自定义客户、账户、交易和对手方节点。用户能追踪邻接关系，但不能把节点距离或颜色直接解释成概率。

关系图必须与案件 ID 对齐，切换标签或案件后不能留下旧节点；没有关系时应清楚说明，而不是渲染假数据填空。

### 第 2 页｜图的可读语义

[figure: 21-react-flow-graph.svg]

不同节点用可读类型标记，边显示交易或手工记录关系。选中节点可查看事实详情；被调查客户突出标记。箭头方向仅代表图数据关系，不表示资金合法或违法。

### 第 3 页｜从合同映射到 Flow 节点

[source: frontend/src/pages/case-detail-page.tsx#function RiskGraph({ caseView }|29]

页面把 `graphNodes` 与 `graphEdges` 映射为 React Flow 需要的节点和边结构。业务合同保留 `Id/Type/Label/Detail`，UI 只转换坐标和视觉样式。关系图列表边可以关联回交易或用户输入理由。

### 第 4 页｜读图与回到源记录

[screenshot: risk-relationship-graph.png]

从客户节点沿账户到交易，再到共同对手方，逐边核对事实来源。若发现客户间通过同一企业连接，下一步是查企业身份与交易背景，而不是仅凭一张图就提交升级决定。必要时在案件中建立带理由的人工关系，后续可在审计记录中复查。

### 第 5 页｜练习与本章小结

**练习**

1. 哪些视觉属性能帮助区分节点类型，又不会暗示未经证实的风险概率？
2. 交互图的坐标是否应该作为持久业务数据？
3. 对每条关系，如何让分析员一跳返回原始交易或记录理由？

**小结**：React Flow 提供探索交互；图数据来自后端持久化事实。视觉布局不等于因果、控制关系或风险证明。
