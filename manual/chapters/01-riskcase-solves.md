# 01｜RiskCase 要解决的是什么问题

### 先看业务现场

银行的上游监测程序已经发现一笔不寻常的转账。它把告警交给调查人员；调查人员要核对客户、账户、交易、风险信号和关系，再写下事实并作出处置。真正困难的不是“有没有一个红色分数”，而是多人怎样基于同一组事实留下可复查的判断。

RiskCase 站在告警产生之后。它不处理付款、不改变余额，也不把信号直接等同于欺诈或洗钱。它帮助人调查、协作、复核和记录。

### 应用边界图

[figure: 01-system-boundary.svg]

上游系统拥有交易监测职责；RiskCase 接收它的告警与相关记录。分析员负责解释证据，主管负责独立复核。系统只保存处置记录和建议，不调用核心银行操作。把边界画清楚，可以避免把一个调查应用误做成实时支付平台。

### 把一次告警拆成可调查的事实

<!-- page -->

**已知**：合成告警 UP-TR-00841 给出 87 分，附三笔 Aroha 账户的转出，另有一笔 Mateo 账户的交易；两位客户均出现对手方 CP-845。问题是“哪些事实值得进一步核验”，不是“谁已被证明违法”。

1. 先按外部引用核对四条观察记录，确认时间、方向、金额、账户与来源一致，排除上游重复投递。
2. 展开“交易速度上升”和“出现新交易对手”的说明，检查信号所引用的交易。分数不参与证明这些记录是否真实。
3. 沿客户 → 账户 → 交易 → CP-845 检查共同邻居。共同商户也会产生相同结构，因此把“共享对手方”记为待解释事实。
4. 经办人记录支持证据、反证和未决问题，形成评估后提交。独立主管核查已冻结的依据，再记录本系统内的处置。

**判读**：调查链的产物是可追溯的判断与责任记录。缺少客户经营背景时应明确保留不确定性；任何分数都不能把缺失的事实自动补齐。

### 练习与本章小结

<!-- page -->

**练习**

1. 如果告警包含疑似受骗账户，为什么 RiskCase 仍不应直接冻结账户？
2. 分别写出上游监测系统、RiskCase 和调查人员拥有的职责。
3. 一个风险分数很高但没有解释的告警，调查人员还缺什么信息？

**参考解**

1. 冻结属于账户操作与授权链，本系统只记录调查和建议。高风险提示不足以证明损失或违法，也没有可执行冻结的业务接口。
2. 上游提供有来源的告警与交易观察；RiskCase 保存调查、评估、提交和决定；人员核验证据并承担判断责任。主管决定也只是本系统内的处置记录。
3. 仍缺触发规则、时间窗口、交易引用、客户背景和反证。87 分可以决定先看哪一案，不能回答某笔交易为何可疑。

**小结**：RiskCase 是告警后的调查与决策记录系统。它的价值来自把事实、解释、协作和责任连在一起；风险提示不能替代人的判断。
