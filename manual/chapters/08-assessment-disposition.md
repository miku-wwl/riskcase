# 08｜风险评估与处置

### 责任属于实际作者

主管 S 经办案件、作出评估并提交复核，然后把案件转派给 A。如果只比较最终复核人与当前负责人，S 就可能看起来“独立”。分派说明现在由谁负责，不能证明过去由谁作出判断。

每次评估因此生成不可变的 RiskAssessment，保存等级、完整依据、作者、时间、案件版本和调查基础版本。当前评估是引用这条记录的投影；旧判断不会被下一次修改覆盖。

### 评估、提交与决定各自保留身份

[figure: 08-assessment-review-gate.svg]

所有风险级别都必须经过主管独立复核。主管可以经办或评估，但本案任何一次评估的作者均不能作最终处置。即使先退回、换经办人、再产生新评估，原作者身份仍然保留，不能借命令顺序变成独立复核人。

ReviewedAssessmentId 固定本次提交对象；RiskDecision.AssessmentId 固定最终决定实际对应的评估。历史版本、当前投影和最终决定是不同信息。

领域要求 Reviewing、确定的评估引用、独立的作者身份、有效处置与足够理由。应用层加载完整评估及旧作者来源记录供规则使用，服务器再验证调用人具有当前有效的主管角色。隐藏按钮只能帮助用户理解规则，不能代替这些检查。

### 从确认界面读出需要补充的证据

<!-- page -->

[screenshot: round4/return-dialog.png]

**已知**：主管 S 曾评估 A1=High；退回后交给 A，A 评估 A2=Low 并提交。S 仍拥有主管角色，且已不是当前经办人。

1. 先查本案完整 Assessments 以及 LegacyAssessorParticipation。S 的历史身份仍存在，不能因 A2 替换当前投影而消失。
2. Decide 拒绝 S。界面隐藏或禁用最终决定只是提示；直接 API 请求仍由同一服务器规则拒绝。
3. 另一个未参与历史评估、非当前经办人/提交人且具有当前有效主管角色的 R，才可核对 A2 并决定。决定保存 AssessmentId=A2。

**判读**：本项目选择较强政策：本案任何一次评估的作者均不能最终处置。旧作者未知时也不猜身份放行；应核实原始资料。

### 职责分离的推理练习

<!-- page -->

**练习**

1. 为何当前负责人不能替代 AssessorId？
2. S 作过评估，A 后来重评，S 能否作本案最终决定？依据哪条历史事实判断？
3. 升级调查后本系统进入 Resolved，能否推断外部欺诈团队已经受理？

**参考解**

1. AssignedAnalystId 只说明现在谁经办，无法证明先前谁判断。独立性必须读取不可变评估作者以及可恢复的旧作者来源。
2. 不能。S 的 A1 历史仍在，即使 A 后来作 A2、等级从 High 改 Low，S 仍是本案历史评估作者，必须换独立主管 R。
3. 不能。Escalate 将本系统案件置为 Resolved 并保存决定；外部团队是否接收、是否采取行动不在本系统可证明范围内。

**小结**：评估保存判断与作者，提交冻结评估身份，决定保存复核结论与引用。职责分离必须跨越转派和重新评估而持续成立。
